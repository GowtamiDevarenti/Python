Option 3 - Meeting room Booking System
Build a Python program for managing meeting room bookings.

The system should contain different types of objects that interact with each other.
For example, a booking could connect a customer with something that can be booked.
Bookings should have meaningful behaviour. They might be created, cancelled, changed or checked in different
ways.
The system should keep track of its current state while the program is running.
You decide how bookings, customers, resources and other parts of your system should be represented and how
they relate to each other.
NO database or permanent data storage is required. The data only needs to exist While the program is
running.

Core Expectations
Regardless of which project you choose, the following describes the expected foundation of your project.
These expectations describe what your project should demonstrate, not exactly how you should build it.

Build a Complete and Connected Program
Your project should be one complete system rather than a collection of separate exercises or unrelated code
examples.
The different parts of your program should work together.

Use Object-Oriented Programming
Your program should contain multiple classes with clear responsibilities.
Create objects from your classes and use them as meaningful parts of your system. Your classes should contain
relevant attributes and methods.

Create Relationships and Interactions Between Objects
Objects in your system should not exist completely independently from each other.
They should interact, contain other objects, work with other objects or otherwise be connected as part of the
system.
You decide how these relationships should be designed.

Actions Should Affect the State Of Your System
Actions should have actual consequences in your program.
Something in your system should change as the program runs, and those changes should affect what can
happen later.
The program should not simply create objects and print different messages.

Work With Collections Of Data or Objects
Your program should manage multiple pieces Of information or multiple Objects using appropriate python
collections.
Choose the collection types that make sense for your solution.

Include Meaningful Program Logic
use conditions, Loops, functions and/or methods to solve problems and control how the system behaves.
Avoid building a program that mainly consists Of hard-coded values and print statements.

Handle Invalid or Unreasonable Actions
Your program should prevent or handle situations that do not make sense Within your system.
What those situations are Will depend on your project. You are responsible for deciding Which situations your
program needs to protect against.

Organize the Project Into Multiple Python Modules
Your complete project should not be implemented in one large Python file.
Divide your code into multiple .pyfiles in a way that makes sense for your program.
There is no required number of files or required file structure. The important part is that your organization has a
purpose.

Make the Program Runnable and Demonstrable
There should be a clear way to start your project and demonstrate its main functionaüty.
The program should run without errors during its normal intended use.
